## 0. 왜 이 셋인가

경쟁 서비스 조사 결과 "AI 가 공시를 요약해준다" 는 이미 기본값이다.

- 토스증권 **AI 시그널** (2025-11): 뉴스·공시를 분석해 시장 변동 원인을 서술한다.
- 토스증권 **AI 어닝콜**: 한국어 STT 로 실적발표를 실시간 요약한다.
- Public.com **AI 에이전트** (2026-03), Robinhood **Agentic Trading** (2026-05):
  자연어 지시로 실제 매매까지 수행한다.

이들의 공통점은 결과만 주는 블랙박스라는 점이다. 반면 이 프로젝트는
`theme_metric_sensitivity.beta` 와 재무지표 변화량 Δ 를 곱해 기대 초과수익률을
만드는 **계산식**을 DB 에 들고 있다. 세 기능은 모두 그 계산식을 사용자에게
드러내는 쪽으로 설계했다.

| 기능 | 한 줄 정의 | 노리는 인상 |
|---|---|---|
| 레이더 스코프 | 장중 공시를 원형 레이더에 실시간으로 찍는 화면 | 긴박감, 앱 이름값 |
| 반박 모드 | 리포트가 스스로 자기 약점을 공격하는 버튼 | 신뢰, 정직함 |
| 타임머신 | 과거 공시 시점으로 돌아가 모델을 검증하는 화면 | 증명 가능성 |

구현 난이도는 반박 모드, 타임머신, 레이더 스코프 순으로 올라간다.
발표 임팩트는 그 반대 순서다.

## 1. 레이더 스코프

### 1-1. 화면 설계

원형 스코프 하나가 화면 전체를 차지한다. 공시 한 건이 점 하나다.

극좌표를 다음과 같이 쓴다.

- **각도 θ**: 그 종목의 primary 테마. 테마 8 개를 원주에 45도 간격으로 배치한다.
  매크로 유전자 군집이 8 개이므로 그대로 대응시킨다.
- **반지름 r**: 나와의 거리. 중심이 내 관심종목이고, 바깥으로 갈수록 멀다.
  연속적인 거리 함수가 아니라 3 단 계단이다. 이유는 §1-2 에 적는다.
  - 1 단, r = 0.15 고정: 내 폴더에 담긴 종목
  - 2 단, r = 0.35 ~ 0.65: 내 폴더 종목과 primary 테마가 같은 종목.
    구간 안의 위치는 `stock_themes.probability` 로 정한다.
    테마 소속 확률이 높을수록 중심에 가깝다.
  - 3 단, r = 0.85 고정: 그 외 유니버스
- **점 크기**: `analysis_reports.expected_car` 의 절대값
- **점 색**: expected_car 의 부호. 양수는 초록, 음수는 빨강, 리포트 없으면 회색
- **깜빡임**: 최근 3 분 이내에 들어온 공시

중심에서 바깥으로 **스윕 라인**이 60 초에 한 바퀴 돈다. 이 주기는 장식이 아니라
`DartPollerScheduler` 의 `fixedDelay` 60 초와 같은 값이다. 스윕이 한 바퀴 돌 때마다
실제로 DART 폴링이 한 번 일어난다. 사용자가 보는 애니메이션과 서버 동작이 일치한다.

점을 탭하면 하단에 카드가 올라온다. 카드에는 종목명, 공시 제목, 기대 초과수익률,
기여도 1 위 지표를 담는다. 카드를 다시 탭하면 리포트 상세로 간다.

### 1-2. 데이터 출처

이미 있는 것은 다음과 같다.

| 필요한 값 | 출처 |
|---|---|
| 공시 메타 | `disclosures` (ticker, title, type, filed_at) |
| 임팩트 | `analysis_reports.expected_car` |
| 테마 각도 | `stock_themes` where `is_primary = true` |
| 내 관심종목 | `favorites` join `folders` on user_id |
| 종목명 | `stocks.name` |

반지름 3 단을 구하는 쿼리는 **세 개 다 이미 있다**. 새로 만들 리포지토리 메서드가 없다.

| 단계 | 쓰는 메서드 |
|---|---|
| 1 단, 내 종목 | `FavoriteRepository.findByFolderUserId(userId)` |
| 2 단, 같은 테마 | `StockThemeRepository.findByStockTickerInAndIsPrimaryTrue(내 티커들)` 로 테마 id 를 모은 뒤 `findByThemeIdAndRank(themeId, 1, pageable)` |
| 3 단, 나머지 | 위 둘에 안 걸리면 기본값 |

없어서 만들어야 하는 것은 **실시간 전달 채널** 하나뿐이다. 현재 구조는 60 초 폴링
후 FCM 푸시와 `notifications` 행 삽입이다. 화면이 계속 열려 있는 동안 점을 흘려보내려면
서버 푸시가 필요하다.

### 1-2-1. 반지름이 3 단 계단인 이유

연속적인 거리 함수는 지금 스키마로 만들 수 없다. 제대로 된 거리를 재려면 종목별
매크로 민감도 벡터가 필요한데, BE 스키마에 그 컬럼이 하나도 없다.

- `theme_metric_sensitivity` 는 테마 × **재무지표** β 다. 매크로가 아니다.
  `metric_code` 는 `financial_metric_catalog` 의 15 개 재무지표를 가리킨다.
- 금리·환율·유가·금 4 축 민감도는 ML 학습 데이터의
  `Interest_stock`, `FX_stock`, `Oil_stock`, `Gold_stock` 컬럼에만 있다.
  BE 로 넘어온 적이 없다.

연속 거리를 원하면 선택지는 두 가지다.

1. 지금처럼 3 단으로 두고, 2 단 구간 안에서만 `stock_themes.probability` 로
   미세 조정한다. 추가 데이터가 필요 없다. 이 문서의 선택이다.
2. `company_macro_sensitivity` 테이블을 새로 만들고 ML 의
   `company_yearly_sensitivities.csv` 를 적재한다. 그러면 코사인 거리로
   진짜 연속값을 쓸 수 있다. 선행 과제가 늘어난다.

### 1-2-2. 2 단이 무너지는 조건

`stock_themes` 가 비어 있으면 2 단에 걸리는 종목이 0 개가 되고 모든 점이 3 단으로
간다. 그런데 이때 더 큰 문제가 먼저 생긴다. **각도축이 아예 그려지지 않는다.**
θ 를 primary 테마로 잡았기 때문이다. 테마가 없으면 레이더가 레이더가 아니다.

업종으로 대체하는 폴백도 지금은 불가능하다. `stocks.category` 컬럼은 있지만
값을 쓰는 코드가 없다. V3 가 심은 placeholder 는 V7 이 지웠고,
`CorpCodeBootstrap` 은 ticker, name, corp_code 만 채운다. 전부 NULL 이다.

따라서 이 기능의 진짜 선행 과제는 반지름이 아니라 ThemeSense 적재다.
§4 의 2 번 항목을 먼저 해결해야 한다.

### 1-3. API 제안

```text
GET /radar/snapshot?window=PT30M
  → 최근 30 분치 공시 점 목록 (화면 진입 시 1 회)

GET /radar/stream            (Server-Sent Event)
  → 새 공시가 생길 때마다 점 1 개를 push
```

SSE 를 고른 이유는 단방향이면 충분하고 WebSocket 보다 가볍기 때문이다.
이벤트 소스는 이미 있는 `DisclosureCreatedEvent` 와 `ReportCreatedEvent` 다.
`AFTER_COMMIT` 리스너를 하나 더 붙여서 SSE emitter 로 흘리면 된다.
기존 두 리스너와 같은 패턴이므로 구조를 깨지 않는다.

점 하나의 payload 는 다음과 같다.

```json
{
  "disclosure_id": 12345,
  "ticker": "005930",
  "name": "삼성전자",
  "title": "현금·현물배당 결정",
  "theta": 135.0,
  "radius": 0.12,
  "expected_car": -1.84,
  "top_metric": "영업이익률",
  "filed_at": "2026-11-12T13:04:22+09:00",
  "is_mine": true
}
```

### 1-4. 엣지 케이스

**공시 폭주.** 장 마감 직후와 분기 보고서 마감일에는 수백 건이 몰린다. 점이 화면을
덮으면 레이더가 아니라 노이즈가 된다. 대응은 두 가지다. 같은 테마·같은 반지름대의
점은 하나로 묶어 숫자 배지를 달고, 내 관심종목이 아닌 점은 초당 유입 상한을 건다.

**리포트가 없는 공시.** `PrimaryFixedRouter` 는 `stock_themes` 가 비면 빈 값을 준다.
학습 유니버스 밖 종목이 여기 해당한다. 이런 공시는 회색 점으로 가장 바깥 링에 찍고
크기는 고정한다. 임팩트를 모른다는 사실 자체를 보여주는 편이 숨기는 것보다 낫다.

**장이 닫혀 있을 때.** 발표는 아무 때나 한다. 빈 레이더를 보여줄 수는 없다.
그래서 **리플레이 모드**가 선택이 아니라 필수다. 과거 특정 일자를 골라 그날의
공시 흐름을 실제 시간 간격의 N 배속으로 재생한다. 데이터는 `disclosures.filed_at`
순서로 읽으면 되므로 추가 저장이 필요 없다.

### 1-5. 데모 시나리오

1. 리플레이 모드로 공시가 많았던 과거 하루를 고른다.
2. 20 배속으로 재생한다. 점이 흩뿌려지고 스윕이 돈다.
3. 내 관심종목 공시가 중심 근처에서 빨갛게 깜빡이는 순간 재생을 멈춘다.
4. 점을 탭해 카드를 띄우고, 리포트 상세로 들어간다.

이 흐름이 발표 영상 도입부 15 초에 들어간다.

## 2. 반박 모드

### 2-1. 화면 설계

리포트 상세 화면 맨 아래에 버튼을 하나 둔다. 문구는 "이 분석이 틀렸다면?" 이다.
누르면 카드가 펼쳐지고, 모델이 자기 근거의 약점을 항목별로 제시한다.

상단에 **신뢰 등급 배지**를 둔다. 상, 중, 하 세 단계다. 등급은 아래 점수로 정한다.

각 항목은 아이콘, 한 줄 요약, 근거 숫자로 구성한다. 탭하면 설명이 펼쳐진다.

### 2-2. 반박 근거 다섯 가지

**(1) 모델 적합도.** `theme_metric_sensitivity.r_squared` 를 쓴다.
0.3 미만이면 "이 테마의 설명력은 낮습니다" 를 띄운다.

**(2) 표본 크기.** `theme_metric_sensitivity.sample_size` 를 쓴다.
100 미만이면 "추정 표본이 적어 계수가 불안정합니다" 를 띄운다.

**(3) 데이터 결측.** 두 군데서 온다. ML 서비스 응답의 `feature_coverage` 가 하나다.
다른 하나는 `MetricDeltaCalculator` 가 Δ 를 0 으로 떨군 지표의 개수다.
상위 5 개 지표 중 2 개 이상이 0 이면 "재무 데이터가 비어 기여도를 계산하지 못한
지표가 있습니다" 를 띄운다.

**(4) 과거 오답.** 타임머신(§3) 의 집계를 재사용한다.
같은 종목·같은 공시 유형에서 모델이 틀린 비율을 보여준다.

**(5) 구조적 한계.** 조건과 무관하게 항상 표시한다. 현재 세 가지가 있다.

- `AnalysisReportGenerator` 는 원시 Δ 를 쓰고 z-score 정규화를 하지 않는다.
  단위가 다른 지표의 기여도를 그대로 더한다.
- `car_lower` 와 `car_upper` 는 `expected_car ± 2` 로 고정된 자리표시자다.
  신뢰구간이 아니다.
- `PrimaryFixedRouter` 는 rank 1 테마 하나만 본다. 2·3 순위 테마의 영향은 버린다.

### 2-3. 신뢰 등급 계산

```text
score = 0
score += (r_squared >= 0.5) ? 2 : (r_squared >= 0.3) ? 1 : 0
score += (sample_size >= 300) ? 2 : (sample_size >= 100) ? 1 : 0
score += (zero_delta_count == 0) ? 2 : (zero_delta_count <= 1) ? 1 : 0
score += (feature_coverage >= 0.9) ? 1 : 0
score += (past_hit_rate >= 0.6 && past_sample >= 10) ? 1 : 0

상 = 7 이상, 중 = 4 ~ 6, 하 = 3 이하
```

임계값은 임의로 정한 값이다. 실데이터가 쌓이면 분포를 보고 조정한다.
이 사실도 구조적 한계 항목에 적는다.

### 2-4. 규칙 기반으로 만드는 이유

LLM 을 쓰지 않는다. 이유가 세 가지다.

- 모든 근거가 DB 컬럼에서 직접 나오므로 생성 모델이 필요 없다.
- 발표 중 외부 API 실패 위험이 없다.
- 같은 리포트는 항상 같은 반박을 내놓는다. 재현 가능하다.

### 2-5. API 제안

```text
GET /analysis/reports/{report_id}/critique
```

응답 예시는 다음과 같다.

```json
{
  "grade": "중",
  "score": 5,
  "items": [
    {
      "code": "LOW_R_SQUARED",
      "severity": "warning",
      "summary": "이 테마의 설명력이 낮습니다",
      "evidence": "R² = 0.31 (권장 0.5 이상)"
    },
    {
      "code": "STRUCTURAL_CAR_BAND",
      "severity": "info",
      "summary": "신뢰구간은 아직 자리표시자입니다",
      "evidence": "car_lower·car_upper = expected_car ± 2 고정"
    }
  ]
}
```

### 2-6. 엣지 케이스

**반박할 거리가 없을 때.** 모든 지표가 양호하면 항목이 비어버린다. 그럴 때도
구조적 한계 세 가지는 항상 남기고, 상단에 "이 리포트는 근거가 비교적 탄탄합니다"
를 띄운다. 빈 화면을 보여주지 않는다.

**자기 폭로의 역설.** `car_lower`·`car_upper` 가 가짜라는 사실을 UI 가 스스로
밝히는 셈이다. 숨기는 것보다 낫다. 심사에서 "이건 왜 ±2 인가" 라는 질문이 나올
때, 이미 앱이 먼저 말하고 있으면 감점이 아니라 가점이 된다.

## 3. 타임머신

### 3-1. 두 가지 모드

**모드 A, 단건 되감기.** 과거 공시 하나를 골라 "그날로 돌아가기" 를 누른다.
화면이 그 시점 리포트를 보여준다. 재생 버튼을 누르면 이후 60 거래일 주가가
선으로 그려진다. 모델이 예측한 수익률 선과 실제 선을 겹쳐 그린다.
방향이 맞았으면 초록, 틀렸으면 빨강으로 영역을 칠한다.

**모드 B, 종목 성적표.** 종목 상세의 분석 탭에 누적 전적을 띄운다.
"이 종목에 대한 모델 적중 11 전 7 승" 형태다. 공시 유형별로 쪼개서 보여준다.
배당 공시는 잘 맞고 유상증자는 못 맞는 식의 패턴이 드러나면 그 자체가 인사이트다.

### 3-2. 적중 판정 규칙

절대 수익률이 아니라 **KOSPI 대비 초과수익률의 부호**로 판정한다.
ML 서비스의 타깃 정의가 이미 초과수익률이므로 기준을 맞춘다.

```text
실제 초과수익률 = 종목 60거래일 수익률 - KOSPI 60거래일 수익률
적중 = sign(expected_car) == sign(실제 초과수익률)
```

`expected_car` 의 절대값이 0.5%p 미만이면 판정에서 제외한다.
모델이 사실상 "모르겠다" 라고 말한 건을 맞고 틀림으로 세지 않기 위해서다.

### 3-3. 없어서 만들어야 하는 것

이 기능은 세 기능 중 선행 과제가 가장 많다.

**(1) 일별 종가 저장소가 없다.** 현재 `/stocks/{ticker}/prices` 는
`NaverDailyPriceClient` 로 매번 외부에서 가져온다. 저장하지 않는다.
60 거래일 뒤 주가를 반복 조회하려면 테이블이 필요하다.

```sql
-- V10 제안
CREATE TABLE daily_prices (
    ticker  VARCHAR(10) NOT NULL,
    trade_date DATE     NOT NULL,
    close   BIGINT      NOT NULL,
    CONSTRAINT pk_daily_prices PRIMARY KEY (ticker, trade_date),
    CONSTRAINT fk_daily_prices_ticker
        FOREIGN KEY (ticker) REFERENCES stocks (ticker) ON DELETE CASCADE
);
```

KOSPI 지수도 같은 방식으로 담아야 초과수익률을 계산할 수 있다.
`ticker = 'KOSPI'` 같은 의사 종목으로 넣거나 별도 테이블을 둔다.

**(2) Look-ahead bias 함정이 있다.** 가장 조심할 부분이다.
"그날 시점의 모델" 을 재현하려면 그날 **공시되어 있던** 재무제표만 써야 한다.
그런데 `financial_statements` 에는 `period` 만 있고 그 수치가 언제 공시됐는지가 없다.
2024 년 3 분기 실적은 2024 년 11 월에 나오는데, 테이블만 보면 9 월 데이터처럼 보인다.
이대로 되감으면 모델이 미래를 본 것처럼 부풀려진 성적이 나온다.

ML 서비스는 이 문제를 이미 인지하고 있다. `LatestPredictionItem` 응답에
`disclosure_date` 와 `financial_age_days` 가 있다. BE 도 같은 값을 저장해야 한다.
V11 에서 `financial_statements.disclosed_at DATE` 를 추가하는 것을 제안한다.

**(3) 생존 편향이 남아 있다.** ML 쪽 `BACKEND_HANDOFF.md` §7 에 명시된 한계다.
현재 유니버스를 과거로 확장했기 때문에 상장폐지 종목이 빠져 있다.
타임머신 성적표에 이 주석을 그대로 달아야 한다.

### 3-4. API 제안

```text
GET /analysis/reports/{report_id}/replay
  → { as_of, expected_car, actual_excess_return, hit, series: [...] }

GET /analysis/{ticker}/track-record?type=quarterly
  → { total, hits, hit_rate, excluded_neutral, by_type: [...] }
```

### 3-5. 엣지 케이스

**표본이 적을 때.** 3 전 2 승을 "적중률 67%" 로 쓰면 거짓말에 가깝다.
10 건 미만이면 비율을 숨기고 "표본 부족 (3 건)" 으로 표시한다.

**60 거래일이 아직 안 지났을 때.** 최근 공시는 판정할 수 없다.
"판정 대기 중, D-23" 으로 표시하고 성적 집계에서 뺀다.

**거래정지와 상장폐지.** 60 거래일을 못 채운다. 판정에서 제외하고 사유를 남긴다.

### 3-6. 반박 모드와의 연결

타임머신 집계는 반박 모드의 네 번째 근거로 그대로 들어간다.
두 기능을 따로 만들지 말고 `track-record` 쿼리를 공유한다.
이 연결 덕분에 반박 모드의 설득력이 눈에 띄게 올라간다.
"과거에 이 종목에서 이만큼 틀렸다" 는 다른 어떤 근거보다 구체적이다.

## 4. 공통 선행 과제

세 기능 전부 아래 항목에 걸려 있다. 우선순위 순이다.

1. **`DART_API_KEY` 발급.** 키가 없으면 `CorpCodeBootstrap` 이 종목 마스터를
   채우지 못해 `stocks` 가 빈 채로 남는다. 공시도 0 건이므로 세 기능 모두
   보여줄 데이터가 없다. 무료이고 즉시 발급된다.
2. **`stock_themes` 적재.** 비어 있으면 `PrimaryFixedRouter` 가 빈 값을 주고
   리포트가 생성되지 않는다. 레이더의 각도 축도 여기서 나온다.
   ThemeSense ETL 산출물이 필요하다.
3. **일별 종가 저장 (V10).** 타임머신 전용이다.
4. **`financial_statements.disclosed_at` (V11).** 타임머신 정확성용이다.
5. **SSE 채널.** 레이더 전용이다. 리플레이 모드만 할 거면 없어도 된다.

|---|---|---|

## 6. 아직 정하지 않은 것

- 레이더의 테마 8 개 배치 순서. 인접한 테마끼리 붙이는 편이 읽기 쉽다.
  매크로 민감도 벡터의 유사도로 정렬하는 방법을 검토한다.
- 신뢰 등급 임계값. §2-3 의 숫자는 근거 없이 정했다.
- 타임머신의 KOSPI 기준 지수. KOSPI 와 KOSPI200 중 무엇을 쓸지 ML 쪽과 맞춰야 한다.
- 반박 모드를 기본으로 펼쳐 둘지 접어 둘지. 접어 두면 아무도 안 누를 수 있다.

## 7. 참고한 경쟁 서비스

| 서비스 | 해당 기능 | 우리와 다른 점 |
|---|---|---|
| 토스증권 AI 시그널 | 뉴스·공시 기반 변동 원인 서술 | 결론만 준다. 계산식을 보여주지 않는다 |
| 토스증권 AI 어닝콜 | 실적발표 실시간 STT 요약 | 요약이지 검증이 아니다 |
| BamSEC | SEC 공시 문장 단위 비교 | 문서 비교이고 수익률 모델이 없다 |
| Composer | 전략 백테스트 | 전략 단위다. 공시 한 건을 되감지 않는다 |
| Public.com, Robinhood | 자연어 지시 자동매매 | 자동화이지 설명이 아니다. 라이선스가 필요하다 |

세 기능 모두 매매를 하지 않는다. 분석과 검증만 한다.
투자자문업 경계를 넘지 않으려면 화면에 교육·분석 목적 문구를 유지해야 한다.
현재 Streamlit 대시보드 하단에 있는 문구와 같은 수준이면 된다.
